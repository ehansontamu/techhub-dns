fix(shipping): use product names instead of HTML order descriptions

Inflow order descriptions can contain complete HTML specification sheets. Prefer
product identity when labelling shipping products, queue items, and packing units
so those sheets do not appear as enormous raw-HTML product titles.

- Resolve names from catalog/embedded product metadata; use a short plain-text
  order label only when actual product names are unavailable.
- Fall back to SKU/product ID for missing names and reject literal/entity-encoded
  HTML descriptions as labels.
- Preserve embedded product names when pick lines contain only partial metadata.
- Keep richer product identity when the same product appears on several orders.
- Correct legacy HTML names in responses without overwriting saved unit weights.
- Use imported catalog names throughout shipping and preserve weights on import.
- Keep matching by Inflow product ID; duplicate SKUs do not merge distinct products.
- Explain catalog name refresh and saved-weight behavior in the product page/guide.

Validation: 108 focused backend tests, frontend lint/build, and a Chromium check
of names, SKU search/fallback, weight saves, catalog refresh, and desktop/mobile
rendering passed. Browser API responses were mocked using a fixture generated by
the backend resolver. No migration or live Inflow/FedEx/printer transaction is
needed to install this fix.
